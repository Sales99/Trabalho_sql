GERAR O SITE DO DICIONÁRIO DE DADOS

1. Objetivo
Gerar, validar e publicar em produção um Dicionário de Dados interativo alinhado às práticas de Governança de Dados (DAMA-DMBOK e COBIT) a partir da documentação do banco de dados do seu grupo (Especificação de Requisitos, DER e Script DDL).

2. Regras de Entrega (Leia com Atenção)
- Formato da Entrega: Envie exclusivamente o link público do seu Dicionário de Dados hospedado no GitHub Pages (ex.: https://seu-usuario.github.io/nome-do-repositorio/). Não envie arquivos compactados (.zip), PDFs ou links do Google Drive/repositório de código-fonte.
- Caráter Individual: Embora a modelagem do banco de dados seja desenvolvida em grupo, a publicação e a entrega são estritamente individuais. Cada integrante deve criar seu próprio repositório público no GitHub e realizar o deploy na sua própria conta. Entregas sem link funcional ou com link repetido entre integrantes não serão consideradas.

3. Instruções de Execução
1. Revisão Prévia dos Artefatos: Antes de gerar o site, garanta que os três documentos do grupo estejam 100% coerentes entre si (Especificação de Requisitos em .pdf, DER em .png e Script DDL em .sql) e livres de textos de template não preenchidos.
2. Geração do Projeto: Utilize o prompt fornecido em anexo (Prompt-Dicionario-Dados-v2.pdf), preenchendo os metadados do projeto (nome, integrantes/papéis como Data Owners e Data Stewards, identidade visual e resumo do negócio) e anexando os três arquivos do banco de dados.
3. Organização de Diretórios: Estruture os arquivos gerados (index.html, style.css, script.js) junto com o PDF de requisitos (na pasta docs/) e a imagem do DER (na pasta assets/), respeitando exatamente os nomes e letras maiúsculas/minúsculas definidos no prompt.
4. Publicação (Deploy): Crie um repositório público na sua conta pessoal do GitHub, envie os arquivos mantendo a estrutura de pastas e ative o GitHub Pages (Settings > Pages > GitHub Actions > Static HTML).

4. Checklist de Validação antes de Enviar o Link
Antes de colar o link na entrega, abra a URL gerada pelo GitHub Pages em uma janela anônima do navegador e verifique se:
[ ] A página carrega completamente sem erros visuais ou de estilização (style.css e script.js ativos).
[ ] Todas as tabelas e colunas do DDL estão presentes, com metadados de governança (LGPD, Linhagem e RBAC) preenchidos.
[ ] A barra de pesquisa filtra tabelas e atributos em tempo real.
[ ] O botão de download abre/baixa corretamente o PDF da Especificação de Requisitos.
[ ] O modal do DER exibe a imagem corretamente com controles de zoom e arraste funcionando.
[ ] O modal do DDL exibe o script SQL completo com destaque de sintaxe e botão de cópia funcional.
